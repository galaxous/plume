# Status Note - 2026-03-24

## Summary

Bu not, 2026-03-24 itibariyla Plume'in gercek readiness durumunu kaydeder.
Ozellikle `native` ve `laradock-bridge` modlari icin "hangi komut yuzeyi var, hangisi gercek runtime orchestration seviyesinde, hangisi henuz eksik" ayrimini netlestirmek icin yazilmistir.

## Native Mode Readiness

### Calisanlar

- `services supported/status/health/logs/up/down/install/update` komut yuzeyi var.
- Servis support matrisi tanimli:
  - `php`
  - `composer`
  - `nginx|apache2|caddy`
  - `mariadb|mysql`
  - `redis`
  - `phpmyadmin`
  - `postgres`
  - `memcached`
  - `rabbitmq`
  - `mongodb|mongo-webui`
  - `mailpit`
  - `meilisearch`
  - `minio`
  - `supervisor`
  - `horizon`
  - `php-worker`
- Port intelligence var:
  - default port doluysa fallback port seciliyor
  - state dosyasina ve SQLite state DB'ye yaziliyor
- Version ve alias davranisi var:
  - PHP alias cozumleme
  - custom version metadata
- Toggle-aware reconcile var:
  - `services update` ile `false -> true` gecisleri algilanabiliyor
- Dependency guard var:
  - `horizon -> supervisor`
  - `phpmyadmin -> PMA_DB_ENGINE + secili db service`
- Site onboarding tarafi native ile en olgun alanlardan biri:
  - `site add/list/check/update/publish/remove`
  - custom server config
  - site bazli php upstream secimi

### Bugun Eksik Olanlar

- Native `install/up/down` akisi gercek package manager ve service manager entegrasyonunu henuz tamamlamiyor.
- Yani bugunku native davranis:
  - state/log/port odakli orchestration modeli
  - fail-fast validation
  - fakat henuz tam `brew/apt/dnf + launchd/systemd/service` provisioning degil
- `workspace` kavrami native modda Laradock benzeri gercek runtime shell/tooling experience seviyesinde degil.
- `redis-webui` native parity implementasyonu henuz yok.
- Production-grade rollback, secrets, TLS, monitoring ve backup kapsamleri phase 9+ alaninda.

### Sonuc

Native mode bugun "iyi bir control plane + stateful orchestration surface" seviyesinde.
Hedeflenen Herd-benzeri "gercek host servislerini tek komutla kurup yoneten production-usable runtime" seviyesine henuz ulasmadi.

## Laradock-Bridge Readiness

### Calisanlar

- `services laradock init`
- `services laradock sync`
- `services laradock check`
- `mode path set/get/use` ile `laradock-bridge` context yonetimi
- Strict Laradock preflight:
  - compose file var mi
  - gerekli servisler tanimli mi
  - `.env` var mi
  - `APP_CODE_PATH_CONTAINER=/var/www` mi
  - `APP_CODE_PATH_HOST` cozumleniyor mu
  - kayitli site path'leri host scope icinde mi
- Site publish/reload tarafinda laradock strict path/compose/container guard var

### Bugun Eksik Olanlar

- Laradock-bridge icin tam service lifecycle parity henuz yok:
  - `services up/down/status/health/logs` komutlari native ile ayni olgunlukta degil
- Live Docker container durumunu state DB ile normalize eden bridge sync eksik
- Full adapter contract eksik:
  - native ile ayni komut, farkli engine mantigi henuz tamamlanmadi
- Safe interoperability ilk adimda var, fakat no-destructive runtime mapping tamam degil
- Laradock strict path/project kurallari bootstrap seviyesinde var; gercek operasyon ve drift takip katmani eksik

### Sonuc

Laradock-bridge bugun "bootstrap + validation + strict boundary guard" seviyesinde.
Hedeflenen "mevcut Laradock stack'i plume ile tek sistem gibi yonetme" seviyesine henuz gelmedi.
